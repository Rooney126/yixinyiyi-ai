步骤0 — 加载
用户上传一个音频文件。librosa.load处理：
检测原始采样率——44100、48000、22050、8000 都有可能。统一重采样到 16000Hz。
立体声合并成单声道。整数 PCM 归一化成 float32 [-1, 1]。
输出一维数组。3 秒音频 → 48000 个采样点。
约束：
大于 30s → 切前 30s
文件损坏 → 返回错误
无最短时长限制（全部交给 VAD 过滤+兜底）

步骤1 — 逐帧RMS能量计算（第一次）
在原始音频上切帧。每帧 2048 个采样点，帧间步进 256。
每帧 RMS：2048 个采样点平方 → 求和 → 平均 → 开根号。输出该帧平均能量。
输出 RMS 数组，长度 ≈ 总采样数 ÷ 256。3 秒音频约 188 帧。

步骤2 — 收集底部 15% 帧的音频拼接成噪声样本【回退机制（15%→20%→…→40%）】
RMS 数组从小到大排列，取底部 15% 帧的索引。
将这些帧对应的原始音频片段（每帧 256 采样点）按时间顺序拼接成连续的 y_noise 数组（不要求帧在原音频中也连续）。
回退：如果总采样点 < 2048，逐步扩大 bottom_pct（15%→20%→…→40%），直到满足为止。

步骤3 — 降噪
使用 noisereduce 库。传入参数：
y = 原始整段音频
y_noise = 上一步找到的连续安静段波形
stationary 由原始音频最小帧 RMS 自适应判断：min_rms < 0.03 → 平稳模式；≥ 0.03 → 非平稳模式
prop_decrease = 0.8
如果 y_noise 长度 < 帧长（2048 采样点），跳过降噪，直接用原始音频。

步骤4 — 逐帧RMS能量计算（第二次）
降噪后音频底噪被压低。原始 RMS 谷底可能 ~0.02，降噪后 ~0.003。能量轮廓变了，需要重新算。
参数相同：2048 帧长、256 步进。

步骤5 — 计算安静值 + Onset/Offset 检测【回退机制（40%→45%→50%）】
在降噪后 RMS 数组上，取底部 40% 帧的中位数作为安静值。
（原用 15%，但降噪后安静帧 RMS 极低，导致阈值过低、多声合并。40% 包含叫声衰减能量，阈值更合理。）
逐帧扫描：
当前不在叫声中：当前帧 RMS > 安静值 × 3.5 → 标记为 onset，进入叫声状态。
当前在叫声中：当前帧 RMS < 安静值 × 3 → 标记为 offset，退出叫声状态。
如果扫描结束仍在叫声状态：最后一帧补偿 offset。

注：原版 Pandeya 论文使用 ×3/×2，经测试对国内手机录音过于保守。经多文件测试校准，×3.5/×3 + bottom 40% 在切分多声、过滤噪声之间取得最佳平衡。

步骤6 — 有效段判断（满足任一即丢弃）
在增加缓冲前，对每一对 onset-offset 做两条检查，全部通过才保留：
条件① — 原始叫声时长 < 0.25s → 丢弃
原始叫声时长 =（offset 帧索引 − onset 帧索引）× 256 ÷ 16000。
CatSound_V2 中所有 < 0.3s 的段 RMS 仅 0.0006，是设备底噪波动。0.25s 放宽了边界但仍需过滤设备底噪。
条件② — 段内最大帧 RMS < 0.01 → 丢弃
段内取 RMS 最大值，低于 0.01 说明整段能量太低，是噪声而非猫叫。

两条全过 → 保留，记录原始叫声时长作为投票权重。

步骤7 — 0.15秒缓冲
每段 onset 前推 0.075s，offset 后推 0.075s。边界夹到音频起止。

第8步 — 重叠段切分（仅当段数 > 1 时执行）
缓冲后段 A 终点与段 B 起点可能重叠（两叫间隔 < 0.15s）。
判断：后一段起点 < 前一段终点 → 重叠。
处理：重叠区找 RMS 最低帧对应采样点，从那里切开。最低点是两叫自然边界——第一声尾巴回落、第二声起音未全起的 RMS 谷底。
单段时不执行切分。

第9步 — 每段Mel预处理
在降噪后音频上取段。
峰值归一化：振幅除以最大值。消除录音音量差异。CNN 应该比较频谱形状，不是学"音量大 = 愤怒"。
Mel 频谱：128 个 Mel 频带，50-8000Hz，n_fft=512（分辨率 31.25Hz），hop=256（分辨率 16ms）。输出 (128, 时间帧数)。
转 dB + 归一化 [0, 1]：线性幅度 → dB（人耳感知是对数）→ 缩放到 [0, 1]。
固定到 80 帧：80 × 256 ÷ 16000 = 1.28s。
CNN 输入必须固定尺寸。最短段（原始 0.25s + 0.15s 缓冲 = 0.4s）80 帧下 pad 22.5%，比 100 帧下 pad 37.5% 有效信号更多。
Mel 帧数 < 80 → 右补零到 80。> 80 → 居中取 80 帧。
输出：(128, 80) float32，值域 [0, 1]。

第10步 — 每段 CNN 推理
(128, 80) Mel → ch64 CNN：4 层卷积 → FDAP 池化（频率分 4 段，各段时间维取均值后拼接）→ 全连接 → 10 类 softmax。
输出：[Angry, Defence, Fighting, Happy, HuntingMind, Mating, MotherCall, Paining, Resting, Warning] 的 10 维概率向量。

第11步 — 等权投票（推理时使用）
同一文件/同次分析的所有段，各段 10 类 softmax 概率取等权平均：vote = probs.mean(axis=0)。
每段一票，不按时长加权。理由：噪声段通常短于猫叫段，等权投票不会放大噪声影响。

训练时：文件级 top-3 投票 loss。每文件所有段中，取最像正确类的前 3 段（top-3），对它们的 softmax 正确类置信度取均值后算交叉熵。
作用：VAD 切出的噪声段（标签噪声）通常正确类置信度低，top-3 自然排除它们，梯度不会被污染。
也等于把训练和推理对齐——推理时多做一步等权投票，训练时靠文件级 top-3 投票过滤段级噪声。
