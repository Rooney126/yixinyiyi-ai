## 1. 音频数据预处理流水线

### 做什么与输入输出
任意音频文件（webm/wav/mp3，8k~48k 任意采样率、任意声道）→ 重采样 16kHz 单声道 → 降噪 → VAD 切出猫叫段 → 每段输出 `(128, 80) float32` Mel 频谱（值域 [0,1]）。这是全系统唯一的数据入口规格，训练与推理两端都必须产出 bit 级同分布的 Mel。

11 步规格（权威定义：`音频数据预处理流程.txt`；训练实现：`train/train/train_cnn_pipeline_v2_vadexp.py`；线上实现：`app/cloud_server.py` 的 `process_audio()`）：
0) librosa.load →16k mono，上限 30s；1) 原始帧 RMS（帧长 2048 / 步进 256）；2) 底部 15% 帧的音频**按帧拼接**为噪声样本（不足 2048 点则 15%→40% 步进 5% 回退）；3) noisereduce 降噪（prop_decrease=0.8，min_rms<0.03 自适应平稳/非平稳）；4) 降噪后重算 RMS；5) 安静值=底部 40% 帧中位数，onset=安静×3.5 / offset=×3（仍失配则 40%→50% 回退）；6) 过滤段：原始时长<0.25s 或段内最大 RMS<0.01；7) onset/offset 各加 0.075s 缓冲；8) 重叠段在重叠区 RMS 最低帧处切开；9) Mel：峰值归一化→128 带 / 50-8000Hz / n_fft=512 / hop=256→dB→[0,1]→固定 80 帧（短补零/长居中裁剪）；10) 每段独立过 CNN；11) 多段**等权投票**（probs.mean(axis=0)）。

### 关键技术决策及为什么
- **噪声样本"拼帧"而非"最长连续段"**：真实录音安静帧常不连续，找连续段会失败（youtube01130 高底噪文件案例），拼帧保证降噪永远有素材。
- **安静值 bottom 15%→40%**：降噪后安静帧趋于绝对无声（RMS≈0.003），阈值过低导致一串叫声合并成一段；40% 把叫声衰减尾巴包含进来，阈值更稳。
- **onset/offset ×3.5/×3**：Pandeya 论文原版 ×3/×2 对国内手机录音过于保守，多文件实测校准（memory.md 2026-07-11 记录了从 ×1.5/×1.2 到 ×3.5/×3 的完整演化）。
- **<0.25s 即弃 + 最大 RMS≥0.01 双门槛**：CatSound_V2 中所有 <0.3s 段 RMS 仅 0.0006，是设备底噪波动不是猫叫。
- **等权投票而非时长加权**：噪声段通常短于猫叫段，时长加权会放大噪声影响；训练侧用文件级 top-3 投票 loss 对齐（自动排除 VAD 切出的标签噪声段）。
- **固定 80 帧=1.28s**：最短有效段（0.25s+0.15s 缓冲）在 80 帧下补零 22.5%，比 100 帧方案（37.5%）有效信号占比更高。

### 踩过的坑与解法
- 降噪后能量轮廓变化，必须**重算 RMS**（步骤 4），否则 VAD 阈值失配——线上 `process_audio` 与训练管线都保留两次 RMS。
- memory.md 教训三条（原文）："关键文件上交叉验证前不要下结论"、"不要同时改多处逻辑，改一处测一处"、"原版非平稳模式已处理高底噪，加安全检测是画蛇添足"。
- **考古发现**：`train_cnn_pipeline_v2_vadexp.py` 文件头 docstring 仍写着旧参数（onset×3/offset×2、bottom 15%），但代码常量已是 ×3.5/×3、40%（第 64-65 行、283 行缓存参数 `qp40`）——文档注释滞后于代码，以代码为准；该文件另有 `train_cnn_pipeline_v2.py`（原版 A_aug 基线）并存。

## 2. 模型训练（二分类门卫 + 10 类情绪）

### 做什么与输入输出
- **10 类情绪主模型**：Mel 段 `(1,128,80)` → 10 类 softmax（Angry/Defence/Fighting/Happy/HuntingMind/Mating/MotherCall/Paining/Resting/Warning）。输入数据：CatSound_V2（Pandeya 标注体系）+ SpeedPitch 增强（AUG1X，5922 文件→27326 段、2875 只猫）。
- **猫/人二分类门卫**：Mel 段 → 2 类 softmax（猫 1 / 人 0），部署后拦截人声/环境音，只放行猫叫。

### 关键技术决策及为什么
- **主模型 FDAPMobileCatCNN（ch64）**：4 层卷积 + FDAP 池化（频率维分 4 段、各段对时间取均值后拼接）+ FC。~70K 参数——为"CPU 云端推理 + 可蒸馏到 MCU"的上限设计。FDAP 对比 GAP 的动机：猫叫声信息在频率分布上高度结构化，分段池化保留频带定位信息（train/analysis/run_fdap_classifier 系列实验支撑）。
- **GroupKFold 按猫 id 分折**：同一只猫的多段录音若跨训练/验证集会泄漏（模型记住个体音色而非情绪），5 折按 2875 只猫分组。
- **从零训练 CNN 而非 SSL 微调**：HuBERT/WavLM freeze/finetune 线都试过（`训练入口hubert_train.py`、`train_teacher_hubert_HuBERT教师蒸馏.py`、Wav2Vec2_嵌入训练.py、compare_models_crossval），最终生产选自研轻量 CNN——部署体积与推理成本差 3 个数量级，精度差距用数据增强与管线质量补。
- **门卫 MiniCatBinary 16→32→64（~23.6K 参数）**：正负样本预处理**完全一致**（同一套降噪+VAD），保证训练/推理分布对齐（二分类门卫训练记录.txt）。负样本用 MagicData-RAMC 中文自由对话 180h。
- **类别不均衡**：sklearn compute_class_weight 加权交叉熵。

### 实测指标（结果 JSON 佐证）
- 10 类 ch64 A_aug（results_20260713_135048.json）：17752 文件 → 27326 段，150ep/bs64/lr1e-3，5 折 mean acc **85.0%**（fold1 86.5% … fold5 84.0%），F1 83.7~86.5%。
- 门卫 5 折（二分类门卫训练记录.txt）：mean Acc 98.83%±0.44，最差折 F1 0.9845。

### 踩过的坑与解法
- VAD 标签噪声（一段文件里混噪声段共享文件标签）→ 文件级 top-3 投票 loss：只对最像正确类的前 3 段算损失，噪声段梯度被自然排除。
- 折间波动 → 选折部署：`fold3_best.pth` 为生产权重（app/model/），export_to_onnx.py 固定用折 3。
- 增强数据混入训练集要防"原始+增强同折"：AUG1X 按文件级 GroupKFold 处理。

# 门卫（预处理缓存后重训）

# HuBERT 对比基线（研究线）

## 3. ONNX 导出与量化

### 做什么与输入输出
- `train/export_to_onnx.py`：`app/model/fold3_best.pth`（PyTorch）→ `app/model/model.onnx`（输入 dummy `(1,1,128,80)`，供云端 ONNX Runtime CPU 推理），并留有 int8 量化接口（`model.quant.onnx`，可选）。
- 导出前自校验：加载后先跑一条 dummy 推理打印参考类别与置信度，导出后可对比 PyTorch/ONNX 输出。
- 门卫：训练记录确认 `models/minicat_binary.pt → minicat_binary.onnx`（伴随 .data 外部权重文件）。

### 关键技术决策及为什么
- **ONNX Runtime CPUExecutionProvider**：阿里云 2C2G 无 GPU，单次推理 (1,128,80) 毫秒级，无需 GPU；waitress 多线程下每请求各开会话共享（cloud_server 全局 session 复用）。
- **TFLite int8 + C 数组双产物**（端侧线）：`train/export_student_tflite.py` 把蒸馏学生模型转 TFLite int8 并生成 `student_model_data.c`，直接编进 T5 固件（TFLite Micro 无文件系统，模型必须编译进 .rodata）。

### 踩过的坑与解法
- ONNX 大权重需外部数据文件（`model.onnx.data`、`minicat_binary.onnx.data`）——部署清单里必须成对上传，漏 .data 会加载失败。
- TFLite 导出走 CPU（`CUDA_VISIBLE_DEVICES=-1`），避免 CUDA 算子干扰 int8 量化。

### 复现命令
```powershell
py -3.10 train\export_to_onnx.py          # fold3 → model.onnx
cd train && py -3.10 export_student_tflite.py   # 学生模型 → TFLite int8 + C 数组
```

### 当前状态与已知债务
- 云端 `model.onnx` 在产（app/model/）；`model.quant.onnx` 未生成（量化接口存在未使用——2C2G 下无需求）。
- 债务：学生模型 TFLite 线停在 `train/output/kd_tiny_mcu/`（fold1 81.5% 段级 F1），未与固件主线合流（见模块 4/7）。

## 4. 端侧推理（C 推理框架）

### 做什么与输入输出
猫背心端侧猫叫识别：麦克风采集 → 端上 TFLite Micro 跑 TinyMCUCatCNN → 结果经涂鸦 DP 上报。核心资产：
- **蒸馏产物**：`train/train/kd_tiny_mcu_distill.py` — Teacher(FDAP ch64, 128×80 Mel, ~70K 参数) → Student(TinyMCUCatCNN, 3Conv+GAP, 64×40 Mel（Teacher Mel 降采样）, ~3K 参数, arena <50KB)。logit 级蒸馏：CE(hard) + T²·KL(soft)。复用 Teacher 的 seg_cache，不增加预处理负担。5 折产物在 `train/output/kd_tiny_mcu/`（fold1 段级 F1 81.5%）。
- **固件侧**：`iot_competition/firmware/model/model_catcnn_data.cc/.h`（C 数组权重）+ `firmware/main/catcnn_test.c`（TFLite Micro 推理与 Mel 测试向量 `test_mel_data.h`）。

### 关键技术决策及为什么
- **知识蒸馏而非直接量化大模型**：70K 参数对 MCU 仍太大（arena<50KB 约束），3K 参数学生 + 输入降采样（128×80→64×40）是能在 T5 上落地的唯一路线。
- **Mel 降采样复用 Teacher 缓存**：学生输入是教师输入的规则降采样，预处理代码零新增。

### 踩过的坑与解法
- （考古）`models/mcu/preprocessed.npz` 是端侧实验的预处理缓存；`tsne_tiny_mcu.py`/`kd_tiny_mcu_distill.py` 并存说明蒸馏过程反复可视化验证。
- TFLite 导出脚本注释明确"用折 1（目前最高 81.5%）"——折选择手工，未自动化。

### 复现命令
```powershell
py -3.10 train\train\kd_tiny_mcu_distill.py      # 蒸馏训练
cd train && py -3.10 export_student_tflite.py    # → .tflite + student_model_data.c
# 固件侧编译进 T5 工程后跑 catcnn_test.c 自检
```

### 当前状态与已知债务
- 状态：**实验完成、未上产线**。学生模型精度（81.5% 段级 F1）与云端教师（~85% 文件级 acc）差约 4 个点。
- 债务：①学生模型未接入背心固件主流程（固件归档的 tuya_main.c 无 CNN 推理调用路径）；②int8 量化后精度损失未单独评估报告。

## 5. 后端服务（cloud_server + 本地 app）

### 做什么与输入输出
`app/cloud_server.py`（~1650 行，Flask）是唯一生产后端：22 条路由 = 页面 5（`/`、`/cats`、`/health`、SPA 兜底、`/stats`）+ 识别 4（predict/feedback/pending 删除/埋点）+ 猫档案 10（cats CRUD/时间线/统计/周报/导出）+ 记录归属 3（认领/删除/未归属）+ 备份 1。predict 全链路：上传 → 11 步管线 → 门卫过滤（softmax>0.5）→ 10 类等权投票 → Paining/Happy 模糊态（top1-top2 gap<0.20）→ 结果落 SQLite records 表（含设备 uid 支持事后认领）。数据飞轮：置信度≥0.8 的样本存 `.npy`/`.json` 到录音目录。

### 关键技术决策及为什么
- **SQLite 单文件 + 每请求短连接**（busy_timeout 5s）：2C2G 单机演示期最简可靠；旧库（users/sessions/feedback）迁移只增表不动旧表，且迁移前自动 `.bak_M1_日期` 快照（红线：数据无损）。
- **限流 10 次/分/IP**（predict 与全部写接口）：无账号系统的公网服务唯一防刷手段；`/stats` 与全量备份共用 `STATS_KEY` 口令（支持环境变量注入）。
- **多段模糊态**：Paining/Happy 置信度接近时输出"不太确定"文案——宁可示弱不误判疼痛，这是宠物健康产品的伦理选择。
- **安全基线**（2026-09-07 冲刺加固）：32MB 体积上限、路径穿越双重闸（静态路由 resolve 校验 + pending 删除 id 白名单）、周报/统计页 HTML 全转义、predict 不回传 traceback、口令 hmac.compare_digest、feedback 类型校验+截断、非 dict JSON body 兜底。
- **privacy_version**：predict 成功响应带 `"v1"`，前端比对 localStorage 版本号强制重弹隐私声明（合规升级通道）。

### 踩过的坑与解法（.bak 考古）
- `cloud_server.py.bak_0806_1900 / bak_0806_2007 / bak_0906` 三个快照对应三轮大改（8 月 6 日两次 + 9 月 6 日 M1 前夜）；`__main__` 启动块曾写在文件中部导致后注册路由全部失效（M1_PROGRESS 2026-09-07 00:15 修复记录）。
- 测试基建：conftest 把代码拷进 pytest /tmp 临时目录再导入，`YXY_DB_PATH` 双保险断言指错即炸——保证测试永不碰真实 data/。

## 7. 固件（宠物智能背心）

### 做什么与输入输出
TuyaOpen 体系的穿戴固件，硬件 = T5 AI Board（bk7258）+ GPS（E108-GN03D@UART2，NMEA0183）+ 加速度计（LIS3DH@I2C1）+ 板载 MIC + LED + 锂电。三大功能：GPS 定位/速度、运动状态（accel）、猫叫采集与翻译（端侧 TFLite CNN 路线或音频上传云端路线）。位置两处：`固件归档/cat-beixin_20260906/`（TuyaOpen 工程归档：src/ include/ dist/ 编译产物 bk7258）与 `iot_competition/firmware/`（比赛交付源码：accel/gps/main + model/model_catcnn_data.cc TFLite Micro 模型数组）。

### 关键技术决策及为什么
- **TuyaOpen + 涂鸦云 DP 数据点**：不自建设备端长连接，GPS/运动/翻译结果都打包 DP 走 tuya_iot_dp_obj_report() → 涂鸦云 → Tuya App；BLE 125kbps（Coded PHY）作无 WiFi 兜底通道。
- **架构选型终版（iot_competition/docs/01_系统架构设计.md v3）：CNN 本地 TFLite 推理**，明确"通信选型 WiFi6 + BLE 125kbps"。
- NMEA 逐字节解析（$GPGGA 定位 + $GPRMC 速度），不依赖整行缓冲——串口流式更抗断帧。

### 踩过的坑与解法
- 固件归档内嵌整套 TuyaOpen（.git/.cache 全量）——归档即"能独立复编译"的快照策略；`tuya_config_secrets.h.example` 模板化密钥（真实 secrets 不入库）。

## 8. 部署与运维

### 做什么与输入输出
- **云生产**：云服务器部署（服务端 + 模型 + 前端静态资源），waitress 多线程，HTTPS 由边缘网络终结。
- **本地演示**：本地启动服务 + 隧道工具暴露到公网域名。
- **运维面**：`/stats?key=` 数据监控页（IP 脱敏/来源分布/家庭视图/回访率）；calls/events/feedback.jsonl 三类日志；数据飞轮样本目录。

### 关键技术决策及为什么
- **Cloudflare Tunnel 而非开放端口**：无需公网 IP/备案证书管理，HTTPS 由 CF 免费；`cert.pem/key.pem` 是本地遗留（部署指南明确不上传）。
- **演示数据副本策略**：`YXY_DB_PATH`/`YXY_RECORDINGS_DIR` 环境变量重定向——demo、pytest、smoke、UI 回归全部跑副本，真实 data/ 只读+md5 清单比对（红线机制，贯穿所有自动化）。
- **三层自动化**：pytest 120（接口/安全/边界）→ smoke_e2e 15 步（API 全链路+红线比对）→ ui_regression 14 步（真实浏览器动线，含隐私弹窗/短录音/下载强断言）。

### 踩过的坑与解法
- 部署指南明确"不上传 server.py/cert/cloudflared/ffmpeg/训练文件"——生产面最小化。
- Playwright Chromium CDN 国内下载不稳 → ui_regression 内置 chromium→msedge→chrome 三级回退（系统 Edge 零下载可用）。
- 中文用户目录是本机头号坑（tempfile/工具链），浏览器装到 `C:\tmp\pw-browsers`、沙盒建在系统临时目录。
